Gate Batches

Work through these batches in order. The counts update when a gate is checked or explicitly deferred with rationale and approver.

Manual Gates

Visual Acceptance

petsfoodstyle
  1. Open `v2-visual-acceptance.html`.
  2. Review every pet at preview and contact-sheet size.
  3. Review food-only and full item contact sheets.

Interactive Installer

NSISinstalluninstall
  1. Run the installer manually.
  2. Choose a temporary install directory.
  3. Launch Deskagotchi from the installed location.
  4. Run uninstall from Windows apps/settings or the generated uninstaller.

Startup On Login

packagedWindows login
  1. Install the packaged app.
  2. Enable Launch on startup in Settings.
  3. Sign out/in or restart Windows.
  4. Confirm Deskagotchi opens once and the pet remains recoverable.
  5. Disable Launch on startup after the test.

This intentionally touches the real Windows startup setting. Do not run it from automated QA.

Physical Monitor Layouts

rightstackedDPI
  1. Run `pnpm run qa:desktop:drag` on each physical layout when available.
  2. Manually drag the pet across displays.
  3. Quit and relaunch to confirm visible restoration.

Real Sleep/Wake

sleepwakeunlock
  1. Launch the packaged or dev app.
  2. Put the machine to sleep for at least five minutes.
  3. Wake and unlock.
  4. Confirm the pet is visible, clickable, and state refreshes.

Environment Edge Cases

RDPtaskbarSmartScreen
  1. Test under RDP if available.
  2. Test with unusual taskbar positions or auto-hide if available.
  3. Record SmartScreen/signing behavior for the installer.

Export

Use this JSON as the manual evidence blob in the V2 audit or PR notes. Checked gates mean tested and passed. Deferred gates require a rationale and an approver in the run context.

Closeout Target

Save or move the exported JSON to `docs/qa/v2-manual-acceptance-export.json`, then run `pnpm run qa:v2:audit --manual docs\qa\v2-manual-acceptance-export.json`. Strict closeout still requires committing the export and refreshed report before `pnpm run qa:v2:closeout` can pass.

Accepted Deferrals

Use these only when a gate is explicitly accepted as out of scope for this V2 release. A deferred gate without rationale or approver still blocks closeout.
