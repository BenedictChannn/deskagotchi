Release stance

Deskagotchi appears close for a Windows-first v0.1 beta-style release, but it should not be presented as broadly release-ready until the final evidence is refreshed on clean main, manual release gates are completed or explicitly deferred, macOS publishing is disabled or tested, and the trust/security notes are made explicit.

Working Decisions

These choices keep the first release smaller and easier to validate.

Windows-first v0.1

Publish Windows first. Do not publish macOS artifacts until a real macOS smoke pass covers first launch, app bundle behavior, and unsigned/unnotarized warnings.

No custom pets in v0.1

Keep built-in package validation internally, but hide or remove user-facing custom pet import/export from v0.1 release surfaces.

Free unsigned beta unless signing is ready

If code signing is not ready, release notes must clearly say the app is unsigned, show the expected SmartScreen caveat, and include checksums.

Public page is part of release readiness

The download page and any release video must only show behaviors present in the exact release candidate, with Windows-first scope and no custom-pet promise.

Public Download Surface

The website/video are trust surfaces, not just marketing. They must make the download obvious while keeping claims narrower than the build evidence.

Landing/docs page content

  • Hero shows the real desktop pet experience, not an abstract app promise.
  • Primary CTA downloads the Windows installer only.
  • Secondary CTA links to GitHub source.
  • Install section explains SmartScreen if unsigned.
  • Trust section states no account, no analytics, no remote sync, and local data only.
  • Known limits section says Windows-first, no custom pets in v0.1, and macOS unavailable unless tested.

Release video guardrails

  • Record against the same installer/release candidate users can download.
  • Show launch, desktop pet, drag, feed/play/clean, settings, and tray recovery.
  • Do not show custom pets, macOS, auto-update, signing, or any unshipped behavior.
  • Keep captions factual: free local Windows beta, not a fully polished cross-platform product.
  • Use the v0.1.0 video shot list as release evidence if it becomes public.

Suggested Completion Order

  1. Hide custom pet import/export and update release claims.
  2. Restrict macOS publishing or require explicit macOS smoke evidence.
  3. Add release workflow guardrails and version/tag checks.
  4. Trim install footprint with locale and dependency packaging changes.
  5. Add Electron navigation/permission denial hardening.
  6. Create the public landing/docs page and release-note copy.
  7. Record or skip the release video; if recorded, verify every shown behavior against the release candidate.
  8. Write v0.1 release notes with checksum, privacy, known limits, and QA scope.
  9. Run full final evidence on clean main and complete manual acceptance export.

Definition of Ready for v0.1

  • Windows installer is built from the exact release commit.
  • Automated checks, desktop QA, idle, and release smoke pass on clean main.
  • Manual installer/startup/sleep/monitor checks are passed or explicitly deferred.
  • Release artifacts match the platform scope being advertised.
  • Release notes are honest about unsigned status and known limits.
  • No user-facing custom pet import/export remains in v0.1.
  • Published installer has a checksum and clear download instructions.
  • Public page and video claims match the release candidate exactly.
