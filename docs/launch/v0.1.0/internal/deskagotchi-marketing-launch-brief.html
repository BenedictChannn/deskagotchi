Deskagotchi marketing launch

Start with proof-led attention, not a hard sell

This brief synthesizes the three launch-strategy reviews into a practical public rollout plan for X, Reddit, short videos, Product Hunt, and Hacker News. It uses the repo launch workflow and positioning doc as the guardrails.

Recommendation X first, GitHub Pages as the home base, GitHub Releases for the installer, Reddit selectively, short videos as proof assets. Skip LinkedIn unless there is a specific reason to use it.

Launch Stance

Deskagotchi should feel like a small indie desktop pet that brings a little life to Windows. The launch should make people feel the care loop first, then trust the download second.

Use nostalgia as the emotional door: "remember checking on a little digital creature?" Then immediately show the current product: a tiny Windows desktop pet you can feed, play with, clean, drag around, and keep nearby while you work.

Warm Specific Founder-led Demo-first No IP-risk comparison No productivity/wellness promise

Account Decision

Do not split attention too early. A personal founder account has more context, personality, and reply credibility than a cold brand account.

Use first

Founder X account

Make the first two weeks founder-led: demo clips, build notes, small pet moments, and replies. Pin a 10-20 second demo once the release link is live.

Reserve lightly

Deskagotchi project handle

Reserve a handle if available, but treat it as a support and release mirror until the project has recurring demand. Keep its purpose distinct from the founder account.

Do not do

Coordinated posting

Avoid duplicate posts across multiple accounts, engagement pods, mass replies, hashtag stuffing, or link-only promotion. Keep replies manual and relevant.

First 30 Days

Use a runway: align truth, show the pet, invite critique, then widen the launch only when the release surface is real.

Days 1-3

Make the public truth real

Publish GitHub Pages, create the GitHub Release, add the final SHA256, confirm signed or unsigned status, and make sure README, release notes, and site agree.

Days 4-7

Light awareness posts

Post two or three media-first X updates: the tiny pet on the desktop, the care loop, and one build/trust note. Keep links secondary unless the post is explicitly about the release.

Days 8-14

Soft beta and critique

Share with a small group or one maker/community venue. Ask for specific feedback: installer friction, first pet choice, care loop, desktop behavior, or copy clarity.

Days 15-30

Wider public push

Publish the public beta thread, one tailored Reddit post if rules allow, and then choose Product Hunt or Show HN only if the app is tryable and you can be present for comments.

X Post Runway

Keep the first posts emotional but concrete. The reader should understand the pet before they are asked to download anything.

First week sequence

  1. "I made a tiny desktop pet for Windows." Use a real 10-20 second desktop clip.
  2. "For people who miss checking on a little digital creature." Show the care loop.
  3. "It lives on the desktop, not in a browser tab." Show drag, tray recovery, and settings.
  4. "What would make this feel more alive?" Ask for one specific critique.

Profile setup

  • Bio: "Building Deskagotchi: a tiny Windows desktop pet beta. Local-first, no account."
  • Header: real desktop screenshot with the pet visible and readable.
  • Avatar: Bao or a clean project icon.
  • Pinned post: demo clip only after the landing page and release link are live.

Video Plan

Yes, make short-form videos. They should be proof-led demos, not hype ads. Most of the marketing value comes from showing the first care moment clearly.

Primary clip

20-35 seconds, vertical 9:16, captions burned in. Empty desktop, pet appears, feed/play/clean, drag around, tiny release CTA.

Reusable variants

1:1 or 4:5 cuts for X/Reddit, 5-8 second loops for replies, and a 45-60 second 16:9 walkthrough for the README/site/GitHub Release.

Must not imply

No macOS support, signed installer, production-ready security, AI companion, custom pets, wellness outcome, or "validated" release unless exact evidence exists.

Content Concepts

Tiny care loop

Hunger drops, snack given, pet mood changes, quick smile. Use it as the emotional anchor.

Lives on desktop

Show the pet near real windows, dragged to a new spot, then recovered from the tray.

Meet the crew

Quick cuts of Bao, Miso, Mochi, Peanut, and Puddles with one tiny personality line each.

Trust note

Installer on GitHub Releases, local save, no account, no analytics or remote telemetry in normal use.

Publish Gates

These gates prevent the marketing from outrunning the product truth.

Before download CTA

Release URL must work

Do not send traffic to /releases/tag/v0.1.0 until the GitHub Release exists publicly and the installer asset is attached.

Before trust claim

Checksum and signing status

Fill the SHA256 from the final release asset and keep unsigned or signed wording exact. Do not reuse a local draft checksum.

Before QA claim

Target release evidence

Use only the QA run tied to the release branch, commit, or release-candidate docs. Do not mine unrelated old .qa-runs.

Source Notes

Platform-specific advice was checked against current official sources on May 17, 2026.

X authenticity

Distinct personal/project accounts are acceptable, but X forbids coordinated inauthentic behavior, duplicate content, engagement inflation, bulk replies, irrelevant hashtags, and link-only spam. Source: X Authenticity policy.

X profile

X profile setup supports header image, profile image, 160-character bio, website, and pinned post. Source: X profile customization help.

Reddit

Reddit warns against repeated or unsolicited mass engagement and recommends posting authentic content in communities where you have a personal interest. Source: Reddit spam policy.

Product Hunt

Product Hunt is useful for early-adopter distribution and feedback, but it says not to ask directly for upvotes; ask people to visit and comment. Source: Product Hunt Launch Guide.

Show HN

Show HN is for something people can try, and the guidelines say not to post if it is not ready for users. Source: Show HN Guidelines.

Short video specs

YouTube Shorts can be up to three minutes when square or vertical, and TikTok's ad specs recommend 9:16 vertical video. Sources: YouTube Shorts help and TikTok video specs.
